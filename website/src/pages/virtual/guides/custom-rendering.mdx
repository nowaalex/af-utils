# Custom rendering

Use the highest API level that can express the required markup. All levels use
the same `VirtualScroller`, item measurement cache, and scroll anchoring.

## High-level list

Choose framework `List` when a scroll element can contain one size element and
one rendered-items block. It owns the required layout refs and subscribes only
to range changes.

- [React list examples](/virtual/examples/react/list/simple)
- [Solid list examples](/virtual/examples/solid/list/simple)

## Framework layout primitives

When the DOM needs extra wrappers or the scroller and items container are not
the same element, use the framework's layout binding instead of `List`. The
[layout elements guide](/virtual/guides/layout-elements) explains the required
DOM, refs, ownership, and scrolling geometry once; this page only helps choose
the appropriate rendering level.

## Fully custom layout

Tables, canvas renderers, and grids may not accept the default block layout.
Subscribe to the necessary event flags and read geometry from the model:

```ts
const unsubscribe = model.subscribe(updateLayout, VirtualScrollerEvent.ALL);

function updateLayout() {
    const before = model.renderedRangeOffset;
    const rendered = model.renderedRangeSize;
    const after = Math.max(0, model.scrollSize - before - rendered);

    beforeElement.style.height = `${before}px`;
    afterElement.style.height = `${after}px`;
}
```

This callback changes DOM geometry without asking React or Solid to render.
Only the view responsible for

<DocLink slug="virtual-core/classes/VirtualScroller#property-from">
    model.from
</DocLink>
through
<DocLink slug="virtual-core/classes/VirtualScroller#property-to">
    model.to
</DocLink>
needs a range subscription.

- [React table renderer](/virtual/examples/react/hook/custom-render)
- [Solid table renderer](/virtual/examples/solid/primitives/custom-render)
- [Two-axis React grid](/virtual/examples/react/hook/grid)
- [Two-axis Solid grid](/virtual/examples/solid/primitives/grid)

Always attach each mounted item using its real index. The core observer then
measures its border box and updates the shared size index; custom layout code
does not need to read `clientWidth`, `clientHeight`, or
`getBoundingClientRect()`.
